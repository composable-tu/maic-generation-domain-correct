# MAIC Generation Domain Correct

OpenMAIC 生成器流水线的领域纠偏改造。

原版 OpenMAIC（v1.0.3）生成器流水线中，AI 仅在大纲阶段才能接触到用户提交的材料，后续阶段 AI 接触的都是 AI 生成产物。这种流水线会放大 AI 幻觉现象。

当 OpenMAIC 生成通识课程的课件时效果还好，因为通识课程基本基于通用常识，预训练大模型能够根据自己的训练材料进行纠偏；而当生成企业非通用领域知识的课件时，原版安排容易使大模型产生并随流水线放大 AI 幻觉，且没有办法纠偏。

> [!note]
> 该纠偏包不适用于通识类课程，因为通识类课程需要模型自身训练数据自纠偏，如果用户材料存在常识问题，模型也能很好的克服。此纠偏包将材料强制作为 AI 第一参考源，可能破坏模型常识纠偏效果。

## 改动说明

相对原包，本包有三处行为变化。

### 纠偏环

每页生成后走一遍自动检查，核对大纲要点、题目、重复出题与图片引用四项，另查正文乱码（生僻字堆叠、整句复读）。

有领域材料时，再用模型按材料复核一遍事实。查出问题自动返工一次；修不好的一般问题照常返回，只有乱码修不好才返回失败。

内部编号漏进旁白会被标出来。

### 讲授口吻

老师按讲课的方式说话：

- 讲知识本身，每段都有具体内容；
- 开场先摆问题再出概念；
- 不点评材料本身，不压缩内容，不说总结总起套话。

### 大纲

一页只讲一两个要点；内容密的主题自动拆成连续多页，不并页省事。

大纲从标题清单变成详细设计：

- 每页自带叙事钩子、必讲命题、误区预警，测验标注每题考查哪个点。
- 材料里的数字、比例、时限必须逐字收进要点，不许改写成“符合规范”这类空话；每页另附 1-3 句原文直引，复核阶段自动拿它当依据。
- 兼容没有这些信息的旧大纲，旧大纲也能在该包流水线推进。

## 纠偏示例

以智谱 GLM 5.3 Flash Low 为模型，以某校实习规定为例。

```txt
为什么要了解实习管理细则

同学们好，欢迎来到今天的课。这一讲我们专门讲实习管理细则。大家先想一想：实习是培养方案里的必修环节，如果你对规则不清楚，最直接的后果可能不是走弯路，而是无法参加实习，或者实习完成绩无法评定。所以这门课的目标很明确——把细则里的关键要求讲透，让你避开所有的坑。
再强调一遍这个利害关系：实习是必修环节，没有替代方案。少了任何一个环节的材料，都可能直接卡住你的成绩。所以这份细则不是可以随手翻翻的文件，它决定了你能不能顺利毕业。
这份细则不是学校随便定的，它有明确的依据——《...本科教学实习管理办法》，文号是...。以后你或者家长想查原文，就按这个文号去找，这是文件的正式出处。
它管哪些实习呢？适用于工程训练、认知实习、专业实习、毕业实习这些集中实践环节。也就是说，你们本科四年里几乎所有要出校门、进车间进企业的实践，都在这个范围内。
整个细则贯穿着十六字原则：安全第一、专业对口、质量为本、分类管理。安全是底线，实习岗位必须和你的专业相关，质量是根本目的，不同类型的实习分门别类管理。后面每一页讲的内容，都是这十六个字的具体展开。
但要注意一个边界：毕业论文（设计）不适用本细则。也就是说，毕业论文有自己的管理规定，不要拿着实习细则的流程去套毕业论文的事。这个区分在后面的手续办理中很重要。
下一页我们就从最基本的分类讲起——四种实习形式，集中与分散的区别在哪里。带着这十六个字，我们继续往下走。

......

已签约毕业生提前离校就业

刚才有同学问：已经签了三方协议，能不能提前离校去上班？可以，但有一条底线要先划清楚。这一页讲的就是已签约毕业生提前离校就业的定位和手续。
最常见的误区是把签约上班当成实习。明确讲：签约上班不等于完成实习，这种离校行为不视为教学实习，不属于人才培养方案规定的实践教学环节。也就是说，它不会替你完成任何实习学分或实习材料，两者的性质完全不同。
那怎么才能合规离校？第一步，填《...提前离校就业承诺书》，也就是附件X，填好后要交毕业论文指导教师审核并签名。注意这一步把论文指导老师也牵进来了，因为离校期间你还要继续做毕业设计，老师需要知道并认可你的离校安排。
第二步是材料提交，一共三样：一是购买提前离校就业保险，保障范围必须覆盖整个离校期间；二是承诺书本身；三是用人单位的接收函，而且必须盖公章。三样缺一不可，接收函没有公章同样无效。
第三步审批备案：辅导员审核之后，报学生工作办公室审批备案。记住关键节点——审批通过后方可离校。材料交了不等于能走，人一定要等批复下来再离开学校，顺序不能颠倒。
最后给一个判别标准和责任界定：某一行为算不算实践教学环节，一律以人才培养方案的规定为准，不要自己想当然。同时明确，离校期间的人身和财产安全责任自负，这就是为什么保险必须先行、承诺书必须签字。下一页我们做一个综合测验，把这堂课的要点全部串起来回顾。
```

## 使用方法

该纠偏包目前仅在 OpenMAIC v1.0.3 上做了验证，其他版本未测试。

### 1. 克隆 OpenMAIC

```bash
git clone https://github.com/THU-MAIC/OpenMAIC.git
cd OpenMAIC
git checkout v1.0.3
```

### 2. 在根 `package.json` 写别名

用 `pnpm.overrides` 做别名替换：

```json
{
  "pnpm": {
    "overrides": {
      "@openmaic/generation": "npm:@composable-tu/maic-generation-domain-correct@x.y.z"
    }
  }
}
```

### 3. 指定包来源并安装

在 OpenMAIC 根目录建 `.npmrc`：

```
@composable-tu:registry=https://npm.pkg.github.com

//npm.pkg.github.com/:_authToken=你的 GitHub Personal Token（Classic）
```

然后重新安装并确认：

```bash
pnpm install
pnpm why @openmaic/generation
```

`pnpm why` 应显示实际安装的是 `@composable-tu/maic-generation-domain-correct@x.y.z`。之后正常启动 OpenMAIC 即可；别名换上后纠偏环默认开启，无需改任何调用代码。如需关闭，调用时传 `correction: { enabled: false }` 即回到单遍生成。

> 也可以直接克隆 `composable-tu/OpenMAIC` 的（`domain-correct`）分支：https://github.com/composable-tu/OpenMAIC/tree/domain-correct
> 
> 该分支不一定随 OpenMAIC 上游同步更新，请留意。
